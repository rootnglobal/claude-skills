## 상장 서류 원문 (중국)
- 거래소 정적 PDF 경로를 직접 검색해 원문을 연다: `static.sse.com.cn`, `static.cninfo.com.cn`, `disclosure.szse.cn`. SSE/SZSE 공시검색 화면은 JS 렌더링이라 Chrome이 필요하다.
- 2차 인용 점유율 표는 근거 B 상한. 모집단 정의 확인 전에는 High 근거로 쓰지 않는다.
- 추출 항목(서브에이전트 프롬프트에 고정): 제품별 매출·판매량·ASP·GPM, 고객별 매출액과 구매 제품 구분, 시장점유율 표(모집단·연도), 경쟁사 사양·가격 비교표, 고객 검증 단계(验证 → 小批量 → 批量), 募投 캐파.
- 고객 목록보다 제품별 판매량·ASP 표가 더 결정적인 경우가 많다. 경쟁사 전체 고성장이 회사와 겹치지 않는 품목에서 나왔는지 확인한다.

## 필수 확인
- 해당 국가에 로컬 경쟁사가 있으면 그 경쟁사의 상장 서류(중국 招股说明书·问询回复, 대만·한국 증권신고서 등)를 1회 확인한다. 시장점유율 표, 고객 검증 단계, 해외 업체 대비 성능·가격 비교가 가장 직접적으로 나온다. 못 열면 Errors에 남기고 근거 B 상한.
- 경영진 주장마다 반대편(고객 또는 경쟁사) 자료를 최소 1건 찾는다.

## 무역통계
- e-Stat: 품별국별 파일 목록은 JS 렌더링, API는 appId 필요('RootN API Keys' 시트에서 확인). 없거나 막히면 UN Comtrade로.
- UN Comtrade public preview API(무키, 월별·국가별, USD만):
  - 호출당 1개월만 허용(콤마 다기간 거부). 1초 간격, 429면 1회만 재시도. 병렬 호출은 429가 늘어난다.
  - 최근 1~2개월은 미공표일 수 있다. 일부 보고국은 403이 반복된다 → Errors에 기록하고 상대국(수입 측) 통계로 대체.
  - 같은 월에 전 HS·전세계 합계가 동시에 약 2배로 뛰면 집계 이상으로 플래그하고 물량 판단에서 제외한다(단가 비율은 사용 가능). 실측: 일본 보고분 2026-04.
  - 월별 루프는 스크립트로 돌리고 요약만 읽는다(공통 규칙 §14).
- HS 선택: 제품 형태(세트 vs 단체 vs 부품)별로 후보를 함께 받는다. 상관이 없는 HS는 기존 트래커 매핑이라도 교체 대상으로 본다.

## FX
- 1순위 FRED(예: EXJPUS). 차단되면 BOJ 時系列統計 → 브로커 리포트의 분기 평균 순으로 폴백.
- BBG 가능 세션이면 `USDJPY Curncy`·`CNYJPY Curncy` 월평균을 BBG_Requests로 요청한다.

## 유료 터미널 (로그인 필요 — 자동화 스케줄에는 쓰지 않음)
- CapIQ(capiq-collector, Chrome 로그인 상태): 고객·경쟁사 transcript(Q&A 포함, 아시아 중소형은 공백 가능), Business Relationships(고객·공급사·경쟁사), Key Developments, 셀사이드(entitlement 범위), 컨센 상세.
  - 종목 MI KEY가 capiq-collector 레지스트리에 없으면 CapIQ 단계는 시작 전에 건너뛰고, 종목 URL 1회 요청을 결과 보고에 싣는다.
  - 관계 데이터는 미국 공시(10-K 등) 기반이라 아시아 고객 커버리지가 약하고 오래된 관계가 섞인다 → 근거 B 상한. 신규 사업 고객 탐색은 경쟁사·고객 상장 서류가 우선.
  - transcript 키워드 검색 위젯은 자동화가 어렵다 → 고객·경쟁사 콜의 회사명 언급 검색은 BBG transcript 검색 요청으로.
- Bloomberg(단말 PC에서 종목 단위 덤프 → bbg-sync): SPLC(고객·공급사 관계와 매출 비중 추정), 엔티티 실적 예정일, BI 산업 리포트, RES 셀사이드, transcript. 세션은 BBG를 직접 쓰지 않고 BBG_Requests에 요청만 남긴다. 기본 덤프에는 SPLC·transcript가 없을 수 있다(컨센·Px만) — 필요하면 요청으로 남긴다.
- 무료 보완: 회사 IR 게시 transcript·결산설명회 Q&A 로그, ログミーFinance, SEC 8-K 첨부, MOPS 법설회 자료.

## 셀사이드
- 공급망·원가 구조(수입비율·FX 민감도·헤지·고객 집중도) 분석이 거의 없는 경우가 많다 → 시장 프레임·신규성 판정용으로 한정한다.
- 파일명에 종목명이 없는 업종 리포트는 종목명·제품어 키워드 스캔만 한다. 전문 읽기는 서브에이전트 다이제스트로.

## 낮은 우선순위
- 직원 리뷰(OpenWork·看准网·Glassdoor·블라인드 등): 경영·인력 신호가 의심될 때 company-review-collector로.
- 채용공고·특허: 특정 가설 검증에 필요할 때만.

## 접근성 메모
- 클라우드 세션 웹 검색은 미국 엔진 → 중국·대만·한국 현지 소스는 현지어 쿼리와 공시 사이트 직접 접근이 필요.
- 샌드박스 curl이 403인 일본 회사 IR·종목 뉴스 사이트는 WebFetch, IR 호스팅 미러(eir-parts 등), TDnet 미러로 대체한다.
- 有報 PDF에서 일본어 폰트 추출이 실패하면 EDINET XBRL·EDINET DB(공통 규칙 §14) 요약으로 대체하고, 확인 못 한 항목(해외조달비율·주요 매입처 등)은 미확인으로 표기.
- JS 렌더링 페이지(일부 거래소·공시 검색·실적 예정일 페이지)는 Chrome으로.
- CAPTCHA가 흔한 곳(일부 조달·세관 통계)은 1회 시도 후 Errors 기록, 대안 경로 제시.

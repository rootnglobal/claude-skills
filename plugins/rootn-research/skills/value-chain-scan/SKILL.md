# value-chain-scan

## 목적
회사 IR이 말하는 이야기를 회사 밖(고객·경쟁사·공급사·end market·현지 데이터)에서 검증해
1) 몰랐던 다운사이드·업사이드 요인을 찾고, 2) 앞으로 추적할 데이터 후보를 명세한다.

뉴스 요약이 아니라 "회사 설명과 외부 증거가 어긋나는 곳"과 "시장이 아직 모르는 것"을 찾는다. 경영진 주장을 반증할 증거를 적극적으로 찾고, 회사 IR·컨센서스를 되풀이하지 않는다.

하지 않는 것(경계):
- 회사 소개·사업 설명 → company-primer
- 투자의견·목표주가·재무모델 수정 → investment-note / financial-model-builder (제안만)
- 피어 간 모멘텀 선별 → peer-momentum-screener
- IR 질문지 작성 → ir-question-prep (질문 후보만 넘긴다)
- 트래커·수집기 구현 → 사용자가 후보를 고른 뒤 별도 작업

## 입력
- 종목명/코드 1개 또는 목록(목록이면 배치 모드).
- 선택: 집중할 사업부·테마, 사용자 메모(걱정 포인트), 비교 기준 시점, 기존 트래커 목록(중복 표시용).
- 선택: 외부 분석 메모(다른 LLM·브로커). 주장별로 1차 출처를 찾아 확인/수정/미확인/보완으로 판정한다(Claims 시트 X 접두 ID, 공통 규칙 §11 전제 검증).
- 모드: full(기본) / refresh(이전 스캔 산출물이 있으면 그 이후 변경분만).

## 원칙
1. 기존 자료 먼저, 재수집 금지: Drive `Investment Research/[종목명 (티커)]/`(섹터 하위 폴더가 있으면 그 아래)의 Model·리서치·IR, 이전 스캔 산출물, BBG 덤프(bbg-sync), CapIQ 수집분(capiq-collector). 같은 세션의 모델·노트 산출물이 있으면 그것부터.
2. 현지어 원문 검색: 대상 국가 언어로 직접 검색한다. 제품 용어는 현지 업계 용어로 — 조사 전에 glossary부터 만든다.
3. 국가 무관: 고객·경쟁사·공급사·생산·판매 국가를 먼저 정하고 해당 국가 소스만 쓴다(references/source_menu.md).
4. 분해: 매출·리스크·업사이드 모두 제품×지역 단위. 한 제품의 추세를 지역 매출 전체에 일괄 적용하지 않고, 시장 성장과 점유율 변화를 분리한다.
5. 근거등급 A~D와 severity 게이트(references/risk_taxonomy.md). D 자료도 버리지 않고 표기하되 게이트 상한을 적용한다.
6. 대칭 검증: 경쟁사·고객의 자기주장도 과장일 수 있다. 반대편(고객 측·경쟁사 측)에서 확인됐는지 구분한다.
7. 신규성: 요인마다 "IR / 셀사이드 / 미인지"를 표시한다. 이미 알려진 것은 짧게.
8. 숫자 창작 금지: 출처 있는 숫자만. 추정은 범위 + 가정을 명시한다.
9. 날짜 구분: 증거의 게시일·이벤트일과 수집일을 분리한다. 늦게 찾은 과거 자료를 새 사건으로 취급하지 않고, 같은 뉴스의 재배포는 독립 증거로 세지 않는다.
10. 저작권: 외부 기사·리포트는 요약·링크만. 유료 터미널(CapIQ·Bloomberg) 내용은 내부 참고·요약만.
11. 토큰: 셀사이드 PDF·내부 문서·긴 자막 원문은 메인 세션에서 전량 읽지 않는다. 서브에이전트 다이제스트나 파일 저장 후 키워드 구간만 읽는다(공통 규칙 §14).

## 절차

### 0. 준비
- 시작 전 `_shared/common-rules.md`(로컬 실행 시 스킬 폴더 기준 `../_shared/common-rules.md`)를 읽고 전 구간에 적용한다 — fail-fast, 자동진행/사전확인, ASCII 파일명, 드라이브 3점 검증, 신뢰도 표기. 그리고 **태스크 완료 후 스킬 피드백 루프(§12)**: 최종 산출물 전달 직후(태스크 단위 1회) 새로 확인된 소스·URL·우회법, 반복된 실패 패턴, 사용자가 수동으로 고친 부분을 점검한다. 개선점이 있으면 수정 지시 txt를 Drive `Skill/` 폴더에 남긴다(SKILL.md 수정은 업무 데스크톱 Claude Code만 SSOT repo claude-skills-2에서 한다). 없으면 "스킬 업데이트 없음" 한 줄로 종료한다.
- 종목 폴더·이전 스캔 확인 → 모드 결정. 기존 모델에서 세그먼트 매출/OP·지역 매출을 인용한다.
- 주가·컨센 스냅샷: 기존 모델·노트 기준일 이후 주가·컨센 변화를 BBG 덤프 Px/Revisions로 확인한다. ±15% 이상이면 원인 확인을 1순위 조사 항목으로 올리되, 같은 날 지수·동종 업종 등락 대비 초과 변동인지부터 본다. 동종주 일별 가격을 웹에서 못 구하면 웹 검색을 반복하지 말고 BBG_Requests에 티커·기간을 남긴다.
- 이벤트 캘린더: 향후 2주 내 자체·핵심 고객·경쟁사 실적 일정을 확인한다. 실적 직전 실행이면 refresh 권장일을 1p 요약에 적는다.
- 같은 종목의 IR 질문지가 있으면 읽어 두고(IR_Questions 중복 제거용), IR 미팅이 72시간 이내면 1p 맨 위에 미팅 일시를 적는다.
- 현재 시장 프레임 3~5줄: 사용자 메모·셀사이드·컨센의 bull/bear 쟁점. 신규성 판정 기준으로 쓴다. 셀사이드는 이 용도로 한정하고, 파일명에 종목명이 없는 업종 리포트는 종목명·제품어 키워드 스캔만 한다.
- 경영진 주장 5~10개 추출: 최근 4분기 결산설명회·콜·有報/사업보고서의 검증 가능한 주장(점유율·가격결정력·수요·진입장벽·고객관계·캐파·마진·신사업).
- 조달 경로와 환율 부담 주체(직수입 / 국내 벤더 / 상사)를 먼저 확정한다. 회사가 외화 매입이 적다고 밝혀도 국내 벤더가 수입하는 구조면 환율 노출은 간접·시차로 존재한다.

### 1. Value chain 지도
- 사업·제품별 매출/OP 비중, 3~5년 성장 기여.
- 제품 → 직접고객 → 최종고객 → end market. 지역 매출은 제품×지역으로 분해한다.
- 회사 지역별 매출 5년 추세를 해당 지역 end market 성장(고객 매출·생산량)과 나란히 놓고, 괴리를 Claims/Factors로 올린다. 고객 국적과 고객 공장 소재지(예: 특정 국가 기업의 제3국 공장 출하)는 분리해 기록한다.
- 고객: 有報 主要な販売先, 고객 공시의 공급사 언급, CapIQ Business Relationships·BBG SPLC(관계·비중 추정치 = 근거 B, 공시로 확인되면 A), 셀사이드. 공개되지 않은 관계는 추정으로 표시한다.
- 경쟁사: 국가별 원어 사명·티커·거래소, 기능 동등성 메모(이름만 비슷하면 제외), 점유율(출처·연도). 근거 C이고 영향 없는 잠재 경쟁사는 Entities에서 생략한다.
- 공급사·핵심 투입재: 집중도, 원산지, 수출통제 대상 여부.
- B2C 리테일·소비재: '고객' 축은 최종소비자 KPI(객수·객단가·기존점)로 대체하고, 직접 상대방은 임대인(출점 형태·폐점 리스크)과 벤더(조달 경로·환율 부담 주체)로 둔다.
- Glossary: 제품 용어 日·简·繁·韓·英.
- 서브에이전트 분담 예: (a) 고객·end market (b) 국가별 경쟁사 (c) 공급·규제·정책·무역통계. 수집은 서브에이전트, 판단은 메인.

### 2. 외부 증거 조사 (`references/source_menu.md` — 해당 국가만)
- 경쟁사 정기보고: 동종 매출·GM·고객·재고·수주, 캐파 증설·철수·가격 정책.
- 경쟁사 상장 서류(중국 招股说明书·问询回复·募投, 대만·한국 증권신고서 등): 로컬 경쟁사가 있으면 원문을 1회 확인한다. 거래소 정적 PDF 경로를 직접 검색해 연다(경로는 source_menu.md). 원문을 못 열면 그 요인의 근거등급 상한을 B로 두고 Errors에 남긴다. 서브에이전트에는 추출 항목을 고정해 준다: 제품별 매출·판매량·ASP·GPM, 고객별 매출액과 구매 제품 구분, 경쟁사 사양 비교표, 고객 검증 단계.
- 라이선시·경쟁사가 상장 그룹의 자회사·JV이면 모회사 연보의 연결 자회사 목록, 합영·연영기업 투자수익, 관련거래 표로 같은 그룹 내 경쟁 채널(다른 라이선스 JV·자체 브랜드)의 상대 성장률을 비교한다.
- IR 기록: 投资者关系活动记录表·互动易/e互动, 대만 법설회, 개인투자자 설명회 Q&A.
- 고객: 최근 2~4분기 실적·콜 — capex 가이던스·재고·멀티소싱·내재화·공급사 언급, 고객 월매출(대만 등). transcript 우선순위: BBG 덤프 > CapIQ > 회사 IR 게시본. 고객·경쟁사 콜에서 회사명 언급 검색은 검색 가능한 경로(BBG transcript 검색 요청)로 하고, CapIQ 검색 위젯 자동화에 매달리지 않는다.
- 피어 교차신호: 같은 고객군에 파는 피어(일본·미국 등)의 지역별 매출 성장률을 회사와 비교한다(국산화·점유율 신호).
- End market: 업계 통계·협회, 수출입 통계(HS), 가격(현물·계약), 정책·보조금·조달·수출통제.
- 업계 영상·발표(선택): 최근 3~6개월 컨퍼런스·경영진 인터뷰·전시회 발언. 절차는 references/industry_video.md.
- 현지어 산업 뉴스. 커뮤니티는 단서로만(1차 소스로 확인 전 Watch 상한).
- 경영진 주장별로 지지 증거와 반증 증거를 정리한다(반증 유형 D1~D10). 주장마다 반대편(고객 또는 경쟁사) 자료를 최소 1건 찾는다.

### 3. 요인 도출 (다운사이드·업사이드)
- references/risk_taxonomy.md 체크리스트(D1~D10·X1~X5·U1~U8)로 빠짐없이 훑는다.
- 점유율 삼각측량: 같은 기간의 시장 성장 / 회사 해당 제품×지역 매출 성장 / 경쟁사 동종 매출 성장 → implied share 변화 범위.
  - 경쟁사 성장은 제품별 판매량×ASP로 분해해, 회사 제품과 겹치는 품목의 성장만 점유율 판단에 쓴다. 경쟁사 고성장을 곧바로 회사 제품 위협으로 읽지 않는다.
  - 경쟁사 고객 목록은 고객별 구매 제품군을 회사 제품과 매칭한 뒤에만 D1/D6 근거로 쓴다.
  - 제3자 점유율 × 시장규모를 회사의 해당 지역 매출과 대조한다. 산술 정합성이 없으면(시장 정의·집계 기준 차이) 그 수치를 영향 계산에 쓰지 않는다.
- 요인별 기록(Factors 시트, 컬럼은 references/output_schema.md): 방향, 유형 코드, 내용, 연결 세그먼트, 근거·등급, 신규성, severity, 확률(낮음/중간/높음 + 근거), 영향 범위, 지역 분리 영향, time-to-impact, tail 플래그, 반증 조건, 다음 확인 시점.
- 영향 계산(Medium 이상): 영향 사업 매출 비중 × 영향 고객 비중 × Q/P 변화 → 매출 영향, 고정비·가동률·증분 마진을 구분해 OP 영향, 그리고 EPS 1줄 환산(세율·주식수 명시). 기존 모델·컨센 대비 차이를 적고, 계산 불가면 불가라고 쓴다.
  - 같은 수요(예: 고객 증설)에 걸린 업사이드·다운사이드는 지역·고객군별로 분리해 이중계상을 피한다.
  - 가이던스 내재 기존점 = 가이던스 매출 성장 − 신규점 기여(최근 월차의 전사−기존점 갭). 신규점 기여를 빼지 않고 역산하면 기존점이 과소 추정된다.
- 반대검증: High 이상(업·다운 모두)은 초안을 보지 않은 서브에이전트에 증거 원문과 요인 한 줄만 주고 "틀릴 이유"를 찾게 한 뒤 반영한다. 점검 항목·반영 규칙은 references/risk_taxonomy.md §반대검증 — 특히 점유율·시장규모의 모집단 정의와 산술 정합성, 최근 6개월 반대 방향 보도, 반론 수치의 1차 출처 확인.

### 4. 추적 데이터 후보
- High·Medium 요인과 핵심 경영진 주장마다, 그것을 앞서거나 직접 보여주는 관측 가능한 데이터를 찾는다: 수출입 통계(국가·HS), 고객·경쟁사 실적·월매출, 업계 지표, 가격, 정책 이벤트 일정, 고객 capex 가이던스 등.
- 수출입 통계는 제품별 HS 후보를 2~3개 뽑아 회사 세그먼트 매출과 각각 리드-래그를 비교한다. 회사가 세트(결합품)로 출하하는지 단체로 출하하는지 확인해 두 형태의 HS를 모두 본다. 기존 트래커의 HS 매핑이 다른 제품의 프록시로 드러나면 '교체/불필요'로 판정한다.
- references/tracker_spec.md 양식으로 명세하고, 데이터를 빠르게 얻을 수 있으면 리드-래그 간이 검증을 실행한다(Python). 원자료와 분기 집계·상관계수는 xlsx의 `Data_{주제}` 시트에 수식(SUMIFS·CORREL)으로 남긴다. 못 하면 "미검증".
- 월차 공표 종목은 2년 스택(전년 동월 + 당해 YoY)이 최근 반기 평균을 유지한다고 가정한 월별 기대치를 Events 임계값으로 쓴다.
- 사용자가 알려준 기존 트래커와 중복을 표시한다. 추천(스케줄 추천 / 실적 시즌 수동 확인 / 불필요)까지만 하고 구현하지 않는다.

### 5. 산출
저장: 종목 폴더 `리서치/`(사용자 지정 위치가 있으면 그곳). 같은 이름이 있으면 `_v2`. 업로드는 공통 규칙 §9(방법 D 또는 커넥터 파일 참조)로 하고 §4로 검증한다. 둘 다 쓸 수 없는 세션은 references/output_schema.md §업로드 폴백(Google Doc·Sheet 변환)을 따른다.
- (a) 보고서 `vcs_{코드}_YYMMDD.docx` (국문, 3~5p, docx 스킬)
  - 1p 요약: 스냅샷 1줄(주가·컨센·다음 이벤트, IR 미팅 임박 시 일시) / 새로 알게 된 것 Top 5(업/다운, 신규성·근거등급) / 흔들리는 경영진 주장 / 다음 결정적 확인 이벤트(날짜) / 추적 추천 Top 3 / IR 질문 후보 Top 3(기존 질문지와 중복이 없으면 그렇게 명시)
  - 이후: value chain 지도(표) → 경영진 주장 vs 외부 증거 → 요인 레지스터(Medium 이상만, Watch는 xlsx에만) → 추적 후보 → 외부 분석 대조 표(입력이 있을 때) → 수집 실패 목록
- (b) 데이터 `vcs_{코드}_YYMMDD.xlsx` (xlsx 스킬): 시트 구성·컬럼은 references/output_schema.md. recalc 후 수식 오류 0을 확인한다.
- (c) 대화 응답: 5줄 내외 — 가장 중요한 신규 요인, 추적 추천, 실패한 소스, 업로드 상태.

### 자기 검토 (5단계 직후)
- 출처 없는 수치, 2차 인용만으로 High 이상이 된 요인, 반대검증을 거치지 않은 High 이상 요인이 남아 있지 않은지 확인한다.
- 1p 요약에 "이 스캔의 결론이 틀릴 가장 큰 이유" 1줄을 적는다.

### 배치 모드 (종목 목록)
- 종목당 서브에이전트 1개가 조사(1~2단계), 메인이 3~4단계 판단·게이트·반대검증. 한 세션 3~4종목 권장, 초과분은 다음 세션 목록으로.
- 종목 간 공통 엔티티(공유 고객·같은 end market·같은 경쟁사)는 1회 조사 후 재사용한다.
- 배치 종료 시 롤업 `vcs_rollup_YYMMDD.xlsx` + 1p 요약(사용자 지정 위치). 시트는 references/output_schema.md §롤업. 진행표(완료/미완료·사유)는 다음 세션이 이어받는다.

### refresh 모드
- 이전 vcs 산출물 이후 변경분만: 요인 상태(new / confirmed / refuted / stale), 경영진 주장 판정 변화, 신규 엔티티, 추적 후보 갱신, Events 시트 판정(긍정/부정 신호 중 어느 쪽이 나왔는지). 보고서는 변경 요약 1~2p.
- 권장 시점: 자체 실적 발표 후, 핵심 고객·경쟁사 실적이 몰린 직후, 사용자 요청 시.

## 연계
- 경영진만 답할 수 있는 미해결 → IR_Questions 시트 → ir-question-prep 입력.
- 직원·고객 리뷰 신호가 필요하면 company-review-collector.
- CapIQ는 capiq-collector(Chrome 로그인 필요). 종목 MI KEY가 capiq-collector 레지스트리에 없으면 CapIQ 단계는 시작 전에 건너뛰고, 종목 URL 1회 요청을 결과 보고에 싣는다.
- Bloomberg는 세션에서 직접 쓰지 않는다. 필요한 항목(SPLC 관계·비중, transcript, 실적 예정일, BI 산업 리포트, 동종주 가격, 환율 월평균 등)을 BBG_Requests 시트에 종목·화면/필드·용도로 남기고, 덤프가 오면 bbg-sync로 인제스트한다.
- 모델 반영이 필요하면 financial-model-builder / investment-note를 제안한다(이 스킬은 모델을 수정하지 않는다).

## 모델·환경
- 판단·종합(3~4단계)은 상위 모델 high effort, 수집 서브에이전트는 중간 모델.
- 권장 환경: Chrome(CapIQ 로그인, JS 렌더링 공시 검색)과 Drive 업로드 경로(공통 규칙 §9)가 있는 데스크톱 세션. 모바일·채팅 세션도 1~5단계를 진행하되 업로드는 §업로드 폴백으로.
- 클라우드 세션의 웹 검색은 미국 검색엔진이라 아시아 현지 소스 커버리지가 약하다 → 현지어 쿼리 + 공시 PDF 직접 fetch + 필요 시 Chrome.
- 가장 비싼 구간은 무역통계 월별 루프와 셀사이드 전문 읽기다. 무역통계 수집은 스크립트로 돌리고 요약만 읽는다(공통 규칙 §14).
- 파일명 ASCII, Python 3.10 호환.

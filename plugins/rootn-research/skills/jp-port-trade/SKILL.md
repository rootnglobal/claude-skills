# jp-port-trade — JP 모델포트 모바일 주문

## 시스템 개요 (매 세션 재설명 불필요 — 이 스킬이 SSOT)

- 포트 시스템: 구글시트 `jp_model_portfolio` + 바운드 Apps Script(v10.x). 거래는 `거래입력` 탭
  (A일자/B티커/D체결가/E Δ%p/M방식/N확정/O입력시각/P메모), 2단계 확정([★거래 확정]) 구조.
- 모바일 주문 경로: 시트 프로젝트의 `OrdersAPI_v1.gs` 모듈이 (a) 텔레그램 명령 폴링(1분),
  (b) 웹앱 doPost API 두 입구를 제공. **어느 경로든 실행은 사용자가 텔레그램에서 `확인 <토큰>` 회신 시에만** 이뤄진다(2FA).
- 확정 후 처리: ORD_CONFIRM_FN이 지정돼 있으면 기존 [★거래 확정] 파이프라인(거래로그·텔레/메일 알림·TWAP대기)까지 자동.
  미지정/실패 시 행은 "확정 대기"로 남고 텔레로 경고(입력시각 기준 TWAP은 유지되므로 경제적 손실 없음).
- 체결가: 잠정가로 기록 후 TWAP 자동 보정(장중 입력=입력시각~종가 TWAP, 장후=익일 TWAP, `고정가`는 보정 제외).

## 클로드 실행 절차

1. **접속정보**: Drive에서 `rootn_jp_port_orders_api.txt` 검색·읽기 → `url=`, `secret=` 파싱.
   파일이 없으면: OrdersAPI 미설치 상태 — 사용자에게 INSTALL_OrdersAPI_v1.md 절차(데스크톱 1회) 안내하고 중단.
2. **주문 해석**: 사용자 요청을 orders 배열로 변환. Δ는 NAV 대비 %p(매도 음수).
   - 기존 종목 비중 조절: `{cmd:'주문', ticker:'6981', delta:0.5}`
   - 전량매도: `{cmd:'청산', ticker:'7532'}` (delta 불필요 — 서버가 현재비중으로 계산)
   - 신규 편입: `{cmd:'신규', ticker:'9983', delta:1.0}` (Watchlist 자동 추가됨)
   - 고정가: `fixPrice: 6900` 추가 (TWAP 보정 제외)
   - 종목명→티커 식별이 모호하면 반드시 사용자에게 확인(순수 식별 질문은 물어봐도 되는 예외).
3. **주문 전 검증(클로드 측 1차)**: 가능하면 시트를 Drive MCP로 읽어 티커가 타깃/보유에 있는지,
   Δ 방향·크기가 사용자 의도와 맞는지 확인. 이상하면 사용자에게 되물을 것.
4. **API 호출** (cloud bash에서 curl):
   ```bash
   curl -sL -X POST '<url>' -H 'Content-Type: application/json' \
     -d '{"secret":"<secret>","action":"prepare","orders":[{"cmd":"주문","ticker":"6981","delta":0.5}]}'
   ```
   - Apps Script 웹앱은 302 리다이렉트를 반환하므로 `-L` 필수.
   - 응답 `{ok:true, preview:[...]}` → 사용자에게: "텔레그램으로 미리보기+6자리 토큰 발송됨.
     **텔레그램에서 `확인 <토큰>` 회신하면 실행됩니다** (10분 유효)". 클로드는 토큰을 알 수 없고 알 필요도 없다.
   - `{ok:false, errors:[...]}` → 거절 사유를 그대로 전달(상한 초과, 미보유 청산, 롱온리 위반 등).
5. **실행 확인**: 사용자가 확인했다고 하면(또는 1~2분 후) `{"action":"status"}` 호출 → 오늘 거래·확정 여부 보고.
   [확정대기]로 남아 있으면 데스크톱 ★거래 확정 필요함을 알릴 것.
6. **실패 처리(fail-fast)**: curl 2회 실패 시 중단하고 URL 만료 가능성(웹앱 재배포 시 URL 변경 → 시트에서
   ord_setup 재실행 필요)을 보고. 반복 재시도 금지.

## 사용자 직접(클로드 없이) 경로 — 안내용

텔레그램 봇 챗에 직접: `주문 6981 +0.5, 7532 +0.5` / `청산 7532` / `신규 9983 +1.0` /
`주문 6981 +0.5 고정가 6900` / `확인 123456` / `취소` / `상태` / `도움말`

## 제약·가드

- |Δ| 상한 기본 3%p(청산 제외). 초과 주문은 서버가 거절 — 사용자가 의도 확인 후 시트 Script Property
  `ORD_MAX_DELTA` 조정 필요.
- 롱온리: 매도 Δ가 보유비중 초과 시 거절. 신규는 `신규` cmd 필수(오타 티커 방지).
- 대기 주문은 한 번에 1배치. 새 prepare가 기존 대기를 덮어씀(텔레에 표시됨).
- 이 API로는 타깃(H) 수정·옵티마이저 실행 불가 — 그건 데스크톱 메뉴의 몫.

## 트러블슈팅

- `{"error":"auth"}`: secret 불일치 — Drive 파일 최신인지 확인(재배포 후 ord_setup 재실행 여부).
- 응답이 HTML 로그인 페이지: 웹앱 액세스가 "모든 사용자"가 아님 — 재배포 필요.
- 텔레 무반응: 폴링 트리거 죽음 — 시트에서 ord_setup 재실행.

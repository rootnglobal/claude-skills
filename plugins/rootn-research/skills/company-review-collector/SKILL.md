# Company Review Collector — 직원·고객 리뷰 수집·투자해석

> **공통 규칙**: 작업 시작 전 `_shared/common-rules.md`(로컬 실행 시 스킬 폴더 기준 `../_shared/common-rules.md`)를 읽고 전 구간에 적용한다 — fail-fast(소스당 1~2회, 로그인·CAPTCHA·무응답이면 즉시 다음 소스), 자동진행/사전확인, ASCII 파일명, 드라이브 3점 검증, 신뢰도 표기, 수집기간 기본 2년, 그리고 **판정 근거 검증(§11)**: 노출·평점은 절대치 단독 금지·표본수(N) 정규화·peer 상대비교·수치 최신성. 그리고 **태스크 완료 후 스킬 피드백 루프(§12)**: 최종 산출물 전달 직후(태스크 단위 1회) 새 소스·URL·우회법, 반복된 실패 패턴, 사용자 수동수정을 점검해 개선점이 있으면 SKILL.md를 고치고 동일 diff를 SSOT repo(claude-skills)에 반영한다(미접근 환경이면 diff 출력 후 flagging). 없으면 "스킬 업데이트 없음" 한 줄로 종료.

리뷰는 **하드데이터를 삼각검증하는 보조지표**다. 익명·표본편향(불만족자·퇴직자 과표집)·조작 가능성 때문에 기본 신뢰도는 세모("신뢰도 낮음")로 두고, 개별 리뷰가 아니라 **집계·추세·peer 대비**로만 판정한다. 목적은 험담 수집이 아니라 (a) 직원 리뷰 -> 경영진 질·사기·이직/감원 신호, (b) 고객 리뷰 -> 제품경쟁력·만족 추세·이탈/불만 신호를 **실적·주가 driver**로 환산하는 것이다.

## 핵심 원칙
- **대상은 주로 일본 기업 -> 일본어 현지 사이트를 1순위로, 일본어로 검색**한다. 회사명은 현지 표기(예: 정식 상호 한자·가나)로 검색해야 리뷰가 걸린다.
- 리뷰 사이트 대부분은 **로그인·회원벽·동적로딩**이 있다. 접근 순서: (1) WebSearch로 현지어 `site:` 쿼리 -> 스니펫/집계평점 확보(로그인 불필요, 최우선), (2) 공개 페이지는 WebFetch, (3) 로그인벽은 사용자가 이미 로그인돼 있을 때만 Claude in Chrome으로 열되 fail-fast. **로그인·페이월 우회를 위해 curl/requests로 긁지 않는다**(web content 제한 준수).
- **employee와 customer를 분리**해 수집·해석한다. B2C면 customer 리뷰 비중을 크게, 순수 B2B/부품사면 customer는 고객사(전방기업) 평판·제품평으로 대체한다(§8-2 supply chain 연계).
- 절대 평점은 무의미 — **업종·국가별 baseline이 다르다.** 반드시 peer 2~3개와 상대비교한다.

## Step 0. 대상 식별
1. 회사명/티커 -> 국가·거래소 확인, **현지어 정식 상호**와 주요 브랜드/제품명 확보(웹서치 1회).
2. 사업 성격 판별: B2C(소비재·앱·리테일·식음료) / B2B(부품·소재·장비·엔터프라이즈SW) / 혼합. 이걸로 customer 소스를 고른다.
3. peer 2~3개 선정(리뷰 상대비교용).
4. 드라이브에 기존 리뷰 자료가 있으면 재수집 전 먼저 재사용(common-rules §2), 로컬 다운로드 폴더도 훑는다(연결 시).

## Step 1. 소스 맵 (국가 x 직원/고객)

### 일본 (1순위)
- **직원(전현직 평가)**: OpenWork(オープンワーク, 旧Vorkers, openwork.jp — 일본판 블라인드·가장 풍부) / 転職会議(jobtalk.jp) / カイシャの評判(ライトハウス, en-hyouban.com) / Indeed 企業レビュー(jp.indeed.com) / キャリコネ(careerconnection.jp, 연봉·리뷰) / エンゲージ会社の評判 / 就活생은 みん就(みんしゅう). 국민연금격 하드지표는 없으나 有価証券報告書의 従業員数·平均勤続年数·平均年間給与와 교차검증.
- **고객(제품 평가)**: 価格.com(kakaku.com, 가전·전자) / @cosme(cosme.net, 화장품) / 食べログ·Googleマップ(점포·외식) / App Store·Google Play 리뷰(앱·SW) / Amazon.co.jp·楽天 리뷰(리테일) / (B2B SaaS) ITreview·BOXIL·G2 / X(旧Twitter) 브랜드 검색 / 5ch·知恵袋(低信頼, candid).

### 한국
- **직원**: JobPlanet(잡플래닛, 최대) / Blind(블라인드, teamblind.com) / 크레딧잡(kreditjob.com — 국민연금 기반 입·퇴사자수·평균연봉·인원증감 = 준하드지표, 별/반) / 사람인·잡코리아 기업리뷰 / OpenSalary.
- **고객**: 네이버 플레이스·쇼핑 리뷰 / 다나와 / 쿠팡 리뷰 / 화해(hwahae, 화장품) / 오늘의집 / App Store·Google Play.

### 미국·글로벌

- **고객**: (B2B) G2·Capterra·TrustRadius / (B2C) Trustpilot·App stores·Amazon·Reddit(서브레딧).

### 중국

## Step 2. 접근·수집 전략
- 소스별 **집계 지표를 먼저** 잡는다: 종합평점(5점 환산), **리뷰수 N**, 최근 12개월 리뷰 흐름, 평점 분포, (앱은) 스토어별·최신버전 평점.
- 로그인벽(OpenWork 일부·転職会議·Glassdoor·JobPlanet 상세)은 검색 스니펫·집계수치로 우회 가능한 만큼만. Chrome은 로그인돼 있을 때만, tabs_context 확인 후 사용하고 fail-fast.
- 원문 리뷰는 **개별 인용 대신 키워드·빈도**로 집계(긍정 top·부정 top). 명예훼손·개인식별 소지 문장은 그대로 옮기지 않고 요약한다.
- 접근 실패는 개별 보고: 사이트·날짜·사유(로그인/차단/무리뷰)·링크.

## Step 3. 지표 추출·정규화
### 직원(employee)
- 종합평점, 세부(경영진·성장성·워라밸·급여·문화·복지), **추천율/"지인에게 추천"·"다시 입사"**, 재직 vs 퇴직 구분, 리뷰수 N, **평점 추세(최근 12M vs 과거)**.
- 자유서술에서 반복 키워드: 긍정(성장·보상·문화) / 부정(이직·야근·경영진·구조조정·연봉동결).
- **이직·감원·구조조정 언급 빈도** = 실행리스크·비용 신호. 한국은 크레딧잡 **입·퇴사자수·인원증감·평균연봉**을 준하드지표로 병기(별/반).

### 고객(customer)
- 종합평점·리뷰수·추세, 앱이면 스토어별+최신버전 평점(하락=이탈 선행).
- 불만 top(품질·AS·가격·배송), 만족 top, **재구매·전환(switch) 언급**, 경쟁사 비교 언급, "가격 대비 가치" 평.
- 순수 B2B면 전방 고객사 제품평·채택 후기(ITreview/G2/전시회·컨퍼런스 반응)로 대체.

## Step 4. 투자 관점 해석 (핵심 — 이 스킬의 목적)
- **직원 리뷰 -> 펀더멘털**: (i) 경영진 질·전략 신뢰, (ii) 사기·이직률(핵심인력 이탈=실행/납기 리스크), (iii) 감원·구조조정·채용동결(비용·수요 선행신호), (iv) 성장 vs 쇠퇴 vibe(리뷰 톤·평점 추세). 크레딧잡/従業員数 증감은 **채용=성장, 감원=위축의 선행지표**. 사업보고서 직원수·근속과 교차검증.
- **고객 리뷰 -> 펀더멘털**: (i) 제품경쟁력·차별화, (ii) 만족 추세(=수요 지속성), (iii) 불만 급증(품질 이슈 -> 반품·워런티·리콜·평판 리스크), (iv) 이탈·전환 신호(=점유율·해지율), (v) 가격결정력("비싸도 산다" vs "가성비 이탈"), (vi) 앱평점·리뷰수 추세(=MAU·리텐션 선행). 매출·재구매율·해지율과 삼각검증.
- **반드시 peer 상대비교**: 평점·추세·불만유형을 경쟁사와 나란히. 절대치 단독 판정 금지(§11).
- **가설로 연결**: "직원 이직 급증 + 경영진 저평가 -> 향후 4~8분기 실행리스크"처럼 timing과 함께 investment-note thesis/리스크로 넘긴다.

## Step 5. 신뢰도·편향 관리 (필수)
- 기본 신뢰도 **세모("신뢰도 낮음", 보조지표)**. 크레딧잡 국민연금 파생·有報 숫자만 별/반.
- **표본수(N)가 작으면(예: <20) 판정 배제**, 참고로만. 최근 12개월 가중.
- **조작 탐지**: 특정 시점 별점 폭탄/일괄 호평(알바성), 평점-서술 불일치, 경쟁·노사분쟁 시기 편향.
- 개별 리뷰 인용 최소화, 집계·패턴 위주. 개인 식별·명예훼손성 문장 원문 전재 금지.
- 읽지 못한/막힌 소스는 명시적으로 flagging.

## Step 6. 산출물·저장·연동
- **기본 산출물**: 국문 리뷰 요약(단독 실행 시 Word `.docx` 1~2p, 다른 스킬이 호출하면 구조화 요약을 반환해 임베드). 구성:
  1. 소스별 표: [사이트 · 국가 · 유형(직원/고객) · N · 평점(5점) · 최근추세 · 긍정top · 부정top · 신뢰도 · 링크]
  2. 종합 해석: 직원(경영진·이직·감원 신호) / 고객(경쟁력·만족추세·이탈·불만) 각 5줄 이내
  3. **peer 상대비교표**(평점·추세·불만유형)
  4. 투자 시사점: 리스크(빨강)·기회(파랑)와 예상 timing(FY1/FY2), 삼각검증 결과(리뷰 vs 실적)
  5. 미확인·차단 소스 flagging
- **저장**: common-rules §2대로 드라이브 종목폴더 `리서치/reviews/`에 업로드(방법 D, 3점 검증), raw 캡처(텍스트/스크린샷)도 보관. ASCII 파일명(예: `sony_6758_reviews_2607.docx`).
- **연동 훅**:
  - `investment-note` §8-2(고객·협력사)와 투자요약 리스크에 요약 주입 -> up/down thesis(§8-10) 정성 근거로.
  - `company-primer` 리스크·moat 섹션 보강, `comparative-investment-note` peer 비교에 리뷰 축 추가, `ir-question-prep`의 bull/bear 텐션·질문 후보로 활용.
  - docx 산출은 docx 스킬(멀티바이트는 heredoc/ASCII 대체) 규칙 준수.

## 원칙
- 리뷰는 정성·보조지표다. 하드데이터(실적·직원수·해지율)와 삼각검증하지 않은 리뷰 단독으로 결론 내지 않는다.
- 험담·개인 식별 인용이 아니라 집계·추세·peer 대비로 말한다.
- 내부 참고용 면책을 포함한다.
